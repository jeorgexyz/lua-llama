## Speculative decoding

| File | Target | Draft | Acceptance |
|---|---|---|---|
| `speculative-correctness.txt` | stories15M | stories15M | 100.0% |
| `speculative-42M-target.txt` | stories42M | stories15M | 82.1% |

```bash
lua54 main_speculative.lua <target.bin> <draft.bin> tokenizer.bin "<prompt>" 60 0.0 4
```

`speculative-correctness.txt` uses the same checkpoint as both draft and target.
That is the invariant test: the draft and the target must agree at every position,
so acceptance is exactly 100% and each round yields the full `lookahead + 1` tokens.
Anything less means the two decode contexts have diverged — which is exactly how a
KV-cache bug in the draft path was caught during development.

`speculative-42M-target.txt` is the real configuration: a 15M draft proposing for a
42M target. Both are TinyStories models sharing a 32000-token vocabulary, so the
draft agrees with the target 82% of the time and each target round yields 4.29
tokens instead of 1.

In both cases the emitted text is **identical** to running the target model alone
under greedy decoding. That is the correctness property of speculative decoding: it
changes how many times the large model is invoked, never what it produces.

## On timing

The wall-clock numbers in these transcripts are *slower* than plain generation, and
that is expected rather than a defect.

Speculative decoding wins when the `lookahead + 1` target positions in a round are
evaluated in a single pass over the target weights — one weight load amortised
across several positions. That is a memory-bandwidth win, and realising it requires
batched matrix multiplication.

Pure Lua has no BLAS, no SIMD, and no batching: every position costs the same
arithmetic whether it is evaluated alone or as part of a block. So the metric that
carries over to a real runtime is **target rounds**, not seconds. 14 rounds in place
of 60 target invocations is the result; converting that into wall-clock time is the
job of a backend this project deliberately does not have.

## Reproducibility

Temperature `0.0` is greedy and fully deterministic — every 0.0 transcript here
reproduces exactly. Temperatures above 0.0 sample and will not reproduce, because
the entry points seed the RNG with `os.time()`.

The larger checkpoints are not committed (`stories42M.bin` is 159 MB,
`stories110M.bin` is 418 MB). Fetch one with:

```bash
curl -L -o stories42M.bin https://huggingface.co/karpathy/tinyllamas/resolve/main/stories42M.bin
```
