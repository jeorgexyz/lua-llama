# Example Output

Real transcripts, generated by running `main.lua` against the `stories15M.bin`
checkpoint committed in this repo. Nothing here is hand-written or edited.

| File | Prompt | Temperature |
|---|---|---|
| `once-upon-a-time.txt` | "Once upon a time" | 0.0 |
| `the-little-robot.txt` | "The little robot" | 0.0 |
| `tim-and-sam-went-to-the-park.txt` | "Tim and Sam went to the park" | 0.0 |
| `temperature-sweep.txt` | "Once upon a time" | 0.0 / 0.7 / 1.0 |

Regenerate any of them with:

```bash
lua54 main.lua stories15M.bin tokenizer.bin "<prompt>" 90 <temperature>
```

## Reproducibility

Temperature `0.0` is greedy decoding — it takes the argmax at every step, so it is
fully deterministic and these transcripts reproduce exactly on any machine. This is
also how the implementation is verified: the greedy continuation of
"Once upon a time" matches what [llama2.c](https://github.com/karpathy/llama2.c)
produces from the same checkpoint, token for token.

Temperatures above `0.0` sample from the distribution and are **not** reproducible,
because `main.lua` seeds the RNG with `os.time()`. The sweep is there to show the
sampler responding to temperature, not to be re-run to identical text. Adding an
optional seed argument would make sampled runs reproducible too.

## What the sweep shows

All three temperatures open with the same words — "there was a little girl named
Lily" — and then diverge. The model and its weights are identical across the three
runs; only the sampling step differs. Higher temperature flattens the distribution
and lets lower-probability tokens through, which is why 1.0 wanders furthest from
the greedy path.
